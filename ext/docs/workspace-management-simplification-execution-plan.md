# 工作区管理收拢：执行计划与检查点

## 实施原则

- 每一步先删除冲突入口和状态，再添加新界面，避免新旧逻辑并存。
- 工作区定义只允许由默认窗口的管理 Tab 写入。
- 已打开工作区不做热更新；所有定义变更以关闭、重开为生效边界。
- 每个阶段完成后必须通过增量编译；涉及启动、持久化或 UI 入口的阶段补充针对性测试。

## 阶段 0：基线与代码地图

工作内容：确认工作区启动、菜单、管理页、持久化、运行时保存和自动推导的入口，记录当前构建基线。

检查点：

- [x] 工作区入口、启动恢复、`LastOpenedWorkspaceId`、锁定/解锁、保存和自动推导调用点均有清单。
- [x] 当前工作树的用户既有改动不被覆盖。
- [x] 默认增量构建可运行。

## 阶段 1：启动与打开策略收紧

工作内容：默认启动不恢复工作区；工作区永远新窗口、锁定打开；已打开时仅聚焦；删除在当前窗口替换/打开和解锁分支。

检查点：

- [x] 普通启动不读取或写入“上次打开工作区”；工作区身份仅随显式的新窗口请求传递，不消费持久化的待启动队列。
- [x] 所有工作区打开路径均计划/执行为新窗口。
- [x] `Locked=false` 不再产生可编辑运行时状态。
- [x] 已打开工作区再次打开时只聚焦原窗口。
- [x] 不存在可达的解锁 UI 或命令。
- [x] 默认窗口的工作区入口为无文本的紧凑图标菜单按钮，与新建 Tab 下拉按钮区分。

## 阶段 2：定义变更入口收拢

工作内容：管理 Tab 仅可在默认窗口打开；移除窗口顶栏保存和运行时自动保存/自动推导写回；移除“行为”与 `OpenInNewWindow` 配置。

检查点：

- [x] 工作区窗口不能打开管理 Tab。
- [x] 默认窗口菜单在“设置”下提供“工作区管理”。
- [x] 运行时命令、目录、标题、颜色、Tab 增删不写回定义文件。
- [x] 管理页不再显示“行为”页面或新窗口开关。
- [x] 保存已打开工作区定义后，界面提示关闭重开生效，且没有热更新调用。

## 阶段 3：管理页模型和交互

工作内容：加入节点默认值；完成左侧新建工作区/节点入口、模板新建、节点拖放排序、自动颜色与重新选择颜色。

检查点：

- [x] 工作区标题和基本情况行右侧均有对应的新增按钮。
- [x] 空白节点仅采用该工作区的节点默认值。
- [x] 模板节点复制配置但生成新 ID、新名称和自动颜色。
- [x] 拖放结果同步更新 `TabOrder` 与节点顺序并持久化。
- [x] 自动配色优先满足本工作区不重复，候选耗尽时回退到确定性派生色。

## 阶段 4：管理页样式与字段精简

工作内容：复用原版设置页的左右表单和 `ToggleSwitch`；重新排列字段；删除自动推导相关字段。

检查点：

- [x] 默认宽度下字段均为左标题、右控件的行式布局。
- [x] 布尔字段使用 `ToggleSwitch`，不再使用 `CheckBox`。
- [x] 节点编辑页依次显示名称、来源、启动命令、启动目录、颜色、是否显示。
- [x] OS、Shell 和推导状态均不显示、不保存。
- [x] 节点名称为单行编辑控件。

## 阶段 5：清理、验证与交付

工作内容：清除废弃持久化字段/状态和不可达分支，完成构建、单元测试与手工 UI 冒烟。

检查点：

- [x] 全仓搜索不再存在可达的最近工作区恢复、解锁、运行时保存或自动推导写回入口。
- [x] 工作区持久化的兼容读取与新格式写入符合设计。
- [x] 默认增量构建成功，必要时执行全量构建。
- [ ] 手工验证默认窗口、管理 Tab、新窗口工作区、已打开工作区重开生效四条主路径。
