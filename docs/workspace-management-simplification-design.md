# 工作区管理收拢与简化设计

## 目标

将工作区从“运行时可保存、可修改、可恢复的会话”收敛为**只能在工作区管理 Tab 中编辑的静态定义**。这次调整优先减少状态、入口和同步逻辑，以降低工作区功能的故障面。

工作区窗口只负责按已保存定义打开和运行；任何定义变更均在默认窗口中的“工作区管理”完成，并在工作区窗口关闭、重开后生效。

## 术语与边界

| 名称 | 含义 |
| --- | --- |
| 默认窗口 | 非工作区方式启动的普通 Windows Terminal 窗口。保留原版终端体验。 |
| 工作区窗口 | 从工作区列表打开的新窗口。启动时加载一个工作区定义，始终处于锁定状态。 |
| 工作区定义 | 持久化的工作区、节点及其默认启动配置。 |
| 管理 Tab | 只在默认窗口中打开的编辑界面，是唯一允许变更工作区定义的入口。 |

工作区的持久化对象和界面文案继续沿用 `Workspace` / `WorkspaceNode` 与“节点”命名，不因本次调整改名。

## 最终行为

### 1. 默认启动

应用默认启动时不读取、不恢复、不自动打开任何上次工作区，也不记录“最后打开的工作区”。窗口表现与原版 Windows Terminal 一致。

默认窗口可以：

- 使用原版新建 Tab、设置和菜单；
- 从原版菜单的“设置”项下方进入“工作区管理”；
- 在管理 Tab 中创建、修改、删除、排序和打开工作区。

### 2. 工作区菜单

工作区菜单只显示：

- 工作区名称；
- 该工作区是否已在窗口中打开；
- 打开一个未运行工作区的动作，或聚焦一个已运行工作区窗口的动作。

默认窗口中的入口为无文本的菜单按钮（50px 宽的双窗口轮廓图标加小下拉箭头），与右侧的“新建 Tab”下拉按钮保持不同的图标、宽度和轮廓；工作区窗口继续显示其名称与锁定状态。

工作区菜单与原版“新建 Tab”下拉框保持相同的底边左对齐弹出方式，并锚定到完整的 24px 触发控件，避免内嵌按钮边框造成额外的间距差异。

菜单中不再提供保存、编辑、锁定/解锁、恢复、在当前窗口打开等动作。

### 3. 工作区窗口

从菜单或管理 Tab 打开工作区时：

1. 始终创建新窗口；
2. 始终以锁定状态加载；
3. 不提供解锁能力；
4. 不在窗口中写回工作区定义；
5. 不根据运行时输入、路径、命令、标题、颜色或节点增删自动更新定义。

同一工作区仍只允许一个已打开窗口：若已打开则聚焦该窗口，不再创建第二个窗口。

管理 Tab 修改已打开工作区时，不尝试对运行中的窗口做增量同步。管理页应提示：**“此工作区正在打开；关闭并重新打开工作区后，变更才会生效。”**

删除一个已打开工作区定义时，允许删除定义；已打开窗口不再获得后续更新，关闭后不能再从列表打开。实现可以在删除前给出同一条“关闭后生效”提示，不要求自动关闭窗口。

## 管理 Tab

### 入口与可用性

入口位于默认窗口原版菜单的“设置”按钮/项下面，名称为“工作区管理”。

- 仅默认窗口显示并允许打开该入口；
- 工作区窗口不显示该入口，也不能通过快捷路径创建管理 Tab；
- 管理 Tab 不属于任一工作区，也不会影响默认窗口的普通 Tab 行为。

### 左侧导航

移除现有“行为”页面及“是否在新窗口打开”开关。左侧仅保留工作区树：

```text
工作区                                              [+]
  项目 A
    基本情况                                        [+]
    API
    Web
  项目 B
    基本情况                                        [+]
    数据库
```

- “工作区”标题右侧的 `+`：新建工作区，并选中新建项的“基本情况”。
- 每个工作区的“基本情况”右侧的 `+`：为该工作区新建节点。
- 新建节点的入口弹出两项：
  - **空白节点**：按该工作区“新建节点默认值”创建；
  - **从已有节点模板创建**：列出该工作区已有节点，复制其配置后创建新节点（新 ID、新名称、自动颜色）。
- 每个工作区下的节点项支持拖放排序。拖放完成后立即更新 `TabOrder` 和 `Nodes` 的显示顺序，并标记管理定义为未保存。

### 基本情况页

基本情况页负责工作区级配置，包括名称、描述、背景色及“新建节点默认值”。

“新建节点默认值”至少覆盖新节点所需的启动相关字段：默认 Profile/连接、启动目录、启动命令、OS、Shell、底部输入面板、是否使用节点名作为 Tab 标题。新建“空白节点”只从这里取值，不再从当前窗口、当前节点或运行时状态推导。

如果现有数据模型没有专门的默认值对象，应新增 `WorkspaceNodeDefaults`（或等价嵌套结构）并序列化；不得把临时 UI 值或最近打开的节点当成默认值。

### 节点编辑页

节点的所有可配置项仅在此页修改。移除原 Windows 顶栏中的保存/更新工作区相关入口，也移除从运行时节点自动保存或推导配置的入口。

节点名称编辑由原本三行（节点名字、同名 label、编辑框）合并为单行：

```text
节点名称： [____________________________]
```

字段修改只写入管理页内存副本；通过管理页的保存动作一次性写入定义文件。保存成功后更新默认窗口的工作区菜单与列表；已打开工作区窗口不热更新。

### 管理页视觉与字段布局

管理页复用原版 Windows Terminal“设置”页的视觉规范和控件风格，而不是自定义表单卡片：沿用原版的页面留白、分组标题、分隔线、字段高度、字体、控件宽度和焦点/禁用态。具体实现优先复用 `TerminalSettingsEditor` 中已有的资源、样式和控件组合。

单项配置改为原版设置页的**左右行式布局**，不再使用“上方 label、下方输入框”的上下堆叠形式：

```text
节点名称                 [____________________________]
来源                     [Profile / SSH / …            ]
启动命令                 [____________________________]
启动目录                 [____________________________]
颜色                     [色块] [重新选择]
是否显示                                      [开 关]
```

- 左列为字段标题和必要的简短说明，右列为编辑控件；窄窗口时可响应式换行，但默认宽度必须保持左右布局。
- 布尔项一律使用原版设置页同款 `ToggleSwitch`，不再使用 `CheckBox`；开关应右对齐，标题/说明在左侧。
- “颜色”行显示当前色块和“重新选择”按钮；不再让用户输入颜色文本。
- 节点名称仍为一行“节点名称 + 编辑框”，不重复显示节点名字或同名 label。

节点编辑页字段顺序固定为：

1. 节点名称；
2. 来源；
3. 启动命令；
4. 启动目录；
5. 颜色；
6. 是否显示；
7. 其余仍保留的纯手工启动选项（如底部输入面板、Tab 标题策略），放在“高级”分组且默认折叠。

“来源”是节点所选 Profile 或 SSH 连接的可编辑选择项；`ProfileGuid`、`ProfileName`、`ConnectionRef` 是其内部保存字段，不应分别暴露为多项文本输入。

以下配置项属于旧自动推导/运行时保存模型，管理页不再显示，也不允许编辑：

- 操作系统（`OperatingSystem`）；
- Shell 类型（`ShellType`）；
- 从当前终端目录、当前命令、标题或输入事件推导的任何中间状态；
- 最近命令、推导路径、推导后的启动命令及其置信度/来源标记；
- 与运行时保存、解锁或当前窗口替换相关的配置。

旧定义中这些字段可被兼容读取以支持既有启动，但保存时应停止写入；后续数据迁移可将其从定义中移除。工作区启动只使用管理页明确保存的来源、启动命令、启动目录和可见性等配置。

### 颜色

每个节点仍有专属颜色。新建节点（空白或模板）均自动选择颜色。

颜色策略：

1. 候选颜色使用固定、可访问性友好的调色板；
2. 排除当前工作区已使用的颜色；
3. 在剩余候选中，选择与当前工作区所有颜色的最小视觉距离最大的颜色；
4. 若候选耗尽，允许复用，但仍选择最能拉开最小距离的颜色；
5. “重新选择颜色”按钮按同一算法重新分配，且优先选取当前工作区未使用颜色；
6. “其他工作区没有”在全局候选仍有空余时一并满足；全局没有可用色时以当前工作区区分度为优先级。

颜色选择只改定义，不修改已经打开的工作区窗口中的节点颜色。

## 必须删除或停用的旧逻辑

以下逻辑与新模型冲突，应在实施中删除，而非保留隐藏分支：

- 默认启动时自动恢复/打开上次工作区；
- `LastOpenedWorkspaceId` 的读写、迁移和兜底逻辑；
- 工作区窗口内的解锁、保存、另存、更新定义入口；
- 从 Windows 顶栏触发的工作区保存逻辑；
- 从输入、当前目录、命令行、终端标题或 shell 事件推导并保存工作区节点配置的逻辑；
- “行为”导航项及 `OpenInNewWindow` 配置；
- 在当前窗口替换/打开工作区的执行分支；
- 管理页保存后向已打开窗口增量应用定义的逻辑。

运行时仍可维护终端自身必要的状态，但不得把它写入工作区定义。

## 数据与兼容性

现有工作区定义可继续读取：

- 所有工作区在加载后视为 `Locked=true`；旧 `Locked=false` 值忽略；
- 保留已有节点配置和顺序；
- 删除 `lastOpenedWorkspaceId` 等运行时恢复状态，加载时不再消费；
- 缺少“新建节点默认值”的旧工作区，使用稳定默认值初始化（全局默认 Profile、空启动目录/命令、默认 OS/Shell），并在用户保存后写入新结构。

不得在加载旧数据时根据活跃窗口、输入历史或终端状态反推默认值。

## 实施切分与验收

建议按以下顺序实施，以便每一步都减少旧分支：

1. 收紧启动与打开策略：默认窗口不恢复工作区；工作区只可新窗口锁定打开。
2. 删除工作区菜单和窗口内的变更入口、保存入口及自动保存/推导链路。
3. 在默认窗口菜单中接入管理 Tab，并限制其只在默认窗口可用。
4. 重构管理页导航：移除“行为”，添加工作区/节点新建入口、模板创建和拖放排序。
5. 增加工作区级节点默认值、自动配色和“重新选择颜色”。
6. 删除 last-opened 和热更新残余代码，补齐迁移与测试。

验收重点：

- 普通启动不触发任何工作区恢复或持久化写入；
- 工作区只能新窗口、锁定打开，且不存在解锁按钮；
- 所有定义变更只能在默认窗口的管理 Tab 完成；
- 编辑已打开工作区后，只有关闭并重开才体现新定义；
- 新建节点的默认值、模板复制、排序与自动颜色均持久化正确；
- 运行终端中的命令、目录、标题和节点操作不会改写工作区定义。
